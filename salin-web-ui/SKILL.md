# Salin Web UI

桌面端网页界面设计与实现：官网 / 营销页、SaaS 工作台与后台、普通网页。信息密度高但不乱，视觉克制可信。

## 任务路由

| 用户目标 | 必读参考 |
|---|---|
| 从零设计网页 | `references/patterns.md` + `references/design-tokens.md` |
| 改造"不好看、太乱、像模板"的已有页面 | 先列问题清单，再读 `references/patterns.md` |
| 工作台 / 后台 / SaaS 功能页 | patterns.md 三栏工作区 / KPI 卡 / 数据表 |
| 在已有代码库中实现 | 先检查项目：README、依赖、路由、组件、tokens、Git 状态 |
| 完成前验收 | 本文件底部「完成前检查」 |

边界按任务目的判断：移动端 App/小程序 → `salin-app-ui`；数据监控、指标诊断、图表联动、独立导航侧栏 → `salin-dashboard-builder`；页面已定、只做 shadcn CLI/组件源码/主题/variants → `salin-shadcn-ui`；功能完成后的只读审查、上线精修 → `salin-ui-quality-audit`。

## 核心流程

1. **确认目标**：页面用户、主任务、主操作、业务约束、可观察的验收标准。非关键缺失可标明假设后继续。
2. **检查现状**：已有项目先读 README、依赖、路由、组件、样式、tokens、环境变量示例和 Git 状态；保留用户未提交修改。
3. **定页面类型**：工作台首页 / 三栏创作工作区 / 数据列表页 / 表单·向导页 / 设置页。
4. **取 tokens**：读 `references/design-tokens.md`。默认「暖纸青墨」；高密度页可用「石墨暖灰」。
5. **选模式**：从 `references/patterns.md` 按页面类型选主模式。创作类页面优先三栏工作区；信息类页面优先 KPI 卡 + 数据表。
6. **实现真实界面**：主流程 + loading / empty / error / 权限 / 长内容 / 超宽屏状态；不虚构业务不存在的状态。
7. **真实验收**：运行项目已有检查，在浏览器走关键流程（含 1280 / 1440 / 1920 三档宽度）；无法验证的明确说明。

## 设计原则

- 桌面端用 8pt 网格；内容区最大宽度 1200~1440px，超宽屏不拉伸。
- 三栏工作区 = 左栏步骤导航（窄）+ 中间画布（最大最亮）+ 右栏参数面板（可折叠）；移动端降级为步骤条 + 单栏，右参数变底部抽屉。
- SaaS、工作台、表单页不拿营销页式大 Hero 挤压操作空间；官网/品牌页首屏必须直接说明主体、价值和下一步。
- 数据表：表头弱化（12px 灰字），行高 ≥ 48px；禁用斑马纹，只用 hover 高亮；状态用胶囊，不用整行色块。
- 可点击元素最小 32px 高；所有图标按钮必须有悬停态（hover 背景或 tooltip）。
- 空 / 加载 / 错误三件套齐全：骨架屏不用"0/空值"误导；错误给重试按钮。
- 表单：必填项标星号；长表单分组 + 分组标题；提交按钮注明消耗（如"生成 · 预计 5 点"）。
- 正文灰不浅于 #6B7280；数字一律 tabular-nums 等宽。
- 禁用：大面积渐变、玻璃拟态、超过 2 层阴影、紫蓝科技风、中文 900 字重。
- 组件动效需要时用 `salin-ui-motion`（点按反馈、弹窗过渡、表单校验等 8 种模式）；动效只服务状态变化，不许抢戏。

## 输出契约

复杂任务先给短方案，然后继续执行：

```markdown
## Web UI 执行方案
- 设计读法：产品 / 用户 / 主任务 / 主操作
- 页面类型：工作台首页 / 三栏工作区 / 数据列表页 / 表单·向导页 / 设置页
- 主模式：patterns.md 中的模式名
- 系统契约：颜色 / 字体 / 间距 / 圆角 / 密度（tokens 来源）
- 完整状态：加载 / 空 / 错误 / 权限 / 超宽屏 / 长内容
- 桌面端自查：8pt 网格 / 悬停态 / 三档宽度 / 空状态
- 实现范围：修改内容 / 保持不动 / 验收标准
```

实现任务完成后汇报关键文件、验证结果、未验证内容和残余风险。只做设计建议时，不擅自扩张到数据库、接口或无关页面。

## 完成前检查

- 首屏能否说明当前页面、关键状态和下一步；SaaS 页主操作是否不被 Hero 挤压。
- 1280 / 1440 / 1920 三档宽度下无错位、无意外横向滚动（数据表内部滚动除外）。
- 所有可点击元素有悬停态/焦点态；键盘可走完核心流程。
- 空 / 错 / 加载 / 权限状态齐全；表格长内容截断有 tooltip。
- 是否在浏览器走过关键流程，而不只依赖代码编译通过。
