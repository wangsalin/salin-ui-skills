# 00 · 项目分析（project）

单页 brief（01）之前，先回答"这是什么项目、给谁用、做什么功能"。输出 `_workbench/project.md`，是所有页面 brief 的共同输入。没有这份文件，单页 spec 就是无源之水。

## 输出字段（`_workbench/project.md`）

### 项目背景
- 一句话：做什么产品，给谁解决什么问题。

### 业务目标
- 可衡量的 1–3 条（如：提升团购核销率、新用户 7 日留存）。写不出可衡量的目标，说明项目还没想清楚，先停。

### 用户分析
- **目标用户群**：画像写关键特征（身份 / 使用场景 / 设备 / 使用频率），3–5 条。不写虚构的姓名年龄故事。
- **核心使用场景**：2–3 个（何时、何地、为何打开）。
- **关键用户旅程**：主流程 3–5 步（如：选场景 → 填卖点 → 生成 → 发布）。

### 功能分析
- **功能清单**：先列全，不许边列边砍。
- **优先级**：P0 必有 / P1 重要 / P2 可砍。P0 超过 7 个说明没想清楚，重排。
- **信息架构**：页面地图（Tab / 页面 / 层级关系），一句话写清每个页面的职责。

### 约束
- 技术栈 / 品牌 VI / 时间 / 项目级不做清单。

## 研究方法（用户分析不是拍脑袋，得有来源）

### 竞品分析框架
1. 找 3 个对标：直接竞品 1–2 个 + 跨界优秀 1 个（不同行业但体验好）。
2. 每个竞品回答：信息架构（几级、几页）/ 核心流程几步 / 视觉语言一句话 / 主操作是什么。
3. 输出一句话结论："我们要做得不一样的地方是 ___" + "要避开的坑是 ___"。
4. 拆布局时复用 `references/02-layout.md` 的九段式。

### 用户访谈提纲模板
- 背景 2–3 问：什么身份？什么场景下用？多久用一次？
- 痛点 2–3 问：现在怎么解决的？最烦的是什么？为这事花过多少钱/时间？
- 验证 1–2 问：给方案第一反应？哪里看不懂？
- 铁律：**不问"你想要什么功能"**，问"你现在怎么做的"。用户要的是更快的马，设计师要看到的是汽车。

## 铁律
- 项目级"不做"先定死，单页 brief（01）不许突破。
- 功能清单先全后砍；用户旅程只写主流程，分支以后再说。
- 本步不讨论视觉、布局、动效——那是后面步骤的事。
