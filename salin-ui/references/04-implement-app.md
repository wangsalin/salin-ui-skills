# 04 · 移动端实现（implement-app）

移动端 App / 小程序的界面设计与实现。先理解产品、用户和主操作，再动手。

## 核心流程
1. 确认目标：页面用户、主任务、主操作、业务约束、可观察的验收标准。
2. 检查现状：已有项目先读 README、依赖、路由、组件、tokens、Git 状态；保留用户未提交修改。
3. 定页面类型：首页 / 列表页 / 表单·向导页 / 结果·成就页 / 我的·设置页。
4. 取 tokens：默认「暖纸青墨」；深色只给结果/成就页（暖黑 + 暖金）；有品牌 VI 的项目品牌优先。
5. 选模式：一屏一主角（一个 Hero 或一个主 CTA，不许 N 个平权入口平铺）。
6. 实现真实界面：主流程 + loading / empty / error / disabled / 权限 / 长内容 / 弱网状态；不虚构业务不存在的状态。
7. 真实验收：在真机或模拟器浏览器走关键流程；无法验证的明确说明。

## 设计原则
- 交互优先级：完成任务 > 理解状态 > 识别层级 > 感受风格。
- 可点击元素最小 44px 高；核心动作放在拇指热区（底部固定按钮或右下 FAB）。
- 空状态不留白：放 3 张建议卡或快捷入口，点一下直接可用。
- 卡片 = 1px 边框 + 12~16px 圆角 + 最多 1 层淡阴影。
- 间距只用 8 / 16 / 24 / 32 / 48 五档；列表行高不小于 44px。
- 状态用小胶囊（6px 色点 + 12px 文字），不用大色块；红色只给真实异常。
- 正文灰不浅于 #6B7280；数字、积分、百分比一律 tabular-nums。
- 组件一律圆角（铁律）。
- 禁用：大面积渐变背景、玻璃拟态、超过 2 层阴影、紫蓝色科技风；中文 900 字重仅限展示型大标题且须风格明确指定（如明黄市集），正文/UI 文字禁用。
- 动效需求查 `data/motions.csv`；动效只服务状态变化，不许抢戏。

## 完成前检查
- 首屏能否说明当前页面、关键状态和下一步操作。
- 主操作是否在拇指热区；危险操作是否有确认或恢复。
- 所有触控目标 ≥ 44px；安全区、刘海屏下无遮挡。
- 空 / 错 / 加载 / 权限 / 弱网状态是否齐全。
