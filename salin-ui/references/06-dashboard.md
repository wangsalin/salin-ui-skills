# 06 · 数据看板（dashboard）

Dashboard 是帮用户"发现变化、理解原因、采取行动"的产品界面，不是卡片和图表的拼盘。仅在数据监控型任务时启用（SaaS 后台、运营看板、数据工作台）。

## 核心流程
1. 定义任务：用户、设备、要监控/比较/诊断/执行的事情，成功标准。
2. 建立页面层级：上下文 → 全局筛选 → 指标摘要 → 主洞察 → 证据 → 行动区。不要先画等宽卡片网格。
3. 设计导航：按导航深度、入口数量、切换频率选侧栏结构；信息架构优先于材质。
4. 设计数据表达：先写用户问题与数据口径，再选最简单足够的图表；定义视觉编码、交互与异常值。
5. 统一状态：筛选、日期范围、路由、图表选择、表格详情的联动和状态所有权，防止各自为政。

## 全局约束
- 一屏先回答一个主要业务问题；其余信息形成清晰次级层级。
- 一张图优先回答一个问题；精确比较优先位置和长度，不滥用面积角度。
- 当前项、数据状态、告警不能只靠颜色表达。
- hover 不能是唯一入口；触摸与键盘必须有等价操作。
- loading / empty / error / 无权限 / 零值 / 缺失值按业务语义处理。
- 权限态（RBAC）：只读用户隐藏操作入口（不只置灰）；无权限页面给原因 + 申请入口，不白屏；禁用态说明原因，不静默失效。
- 移动端不是桌面版缩小：侧栏变抽屉，图表减少同时可见信息。
- 不把推测当项目事实：未知字段/阈值标为"待确认"。

## 高级排版（4 种，后台审美升级用）
一页只做一个判断：整页围绕唯一业务判断组织；指标摘要先行；证据支撑洞察；行动区收尾。

## 完成前检查
- 首屏能否判断"发生了什么、为什么、下一步做什么"。
- 图表口径、单位、轴、阈值真实不误导。
- 侧栏、筛选、图表、表格状态同步。
- 桌面/触摸/键盘/移动端/减少动画都有可用路径。
