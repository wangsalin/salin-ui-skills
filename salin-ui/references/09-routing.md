# 09 · 路由与总控（routing）

本 skill 是单入口：一个 SKILL.md 走完 8 步。下面是何时启用哪个内部模块的路由表，以及跨模块一致性规则。

## 模块路由

| 用户目标 | 启用的模块 |
|---|---|
| 新页面/新项目开工 | 走完整 8 步：01→02→03→04→05→06→07→08 |
| 只做需求定义 | 01-brief |
| 只定风格/多方向二选一 | 02-style |
| 只定布局/拆解现有页面布局 | 03-layout |
| 只查组件规范 | data/components.csv |
| 只做动效 | data/motions.csv（60 种模式）+ 全局动效默认值 |
| 只翻术语 | data/terms.csv |
| 移动端 App/小程序页面 | 04-implement-app |
| 桌面端网页 | 05-implement-web |
| 数据看板/运营后台 | 06-dashboard |
| shadcn 组件工程 | 07-shadcn |
| 只做审查/验收 | 08-audit（默认只读不改） |
| 人说不清想要的动效 | 先查 data/terms.csv 翻成术语（拆 1–3 条、不编造），再查 data/motions.csv 落参数 |

## 总控规则
1. **一次只走一条主线**：移动端和桌面端不同时设计；先定端再动手。
2. **顺序不可跳**：需求→风格→布局→组件→术语→实现→动效→验收。需求变更先改 spec 再动手。
3. **统一读法**：一句话固定页面类型、用户、视觉语言、主操作，避免各步各自选风格。
4. **统一契约**：tokens、状态所有权、响应式、验收标准全页一致；MASTER.md 是跨页面的唯一设计记忆。
5. **动效克制**：仅在信息状态变化、空间关系、品牌表达需要时加入；一屏最多 2 种模式，核心流程只用 1 种。
6. **真实验证**：在真实页面/浏览器走关键流程，不只宣布代码能编译。

## 全局动效默认值（推荐值，非视频原话）
- 时长三档：微反馈 150–200ms；组件过渡 200–300ms；页面/流程切换 300–400ms。
- 缓动：进入 ease-out；退出 ease-in；来回切换 ease-in-out；iOS 可用 spring（damping ≈ 0.8）。
- 位移：底部弹窗 translateY(100%)→0；横滑内容 ±100%；小位移反馈 4–8px。
- 数字滚动一律 tabular-nums；必须尊重 prefers-reduced-motion。

## 何时停下问用户
- spec 确认（第 1 步产出后）
- 风格二选一（第 2 步）
- 其他步骤默认不问，直接走完交付。
