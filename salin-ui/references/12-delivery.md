# 12 · 交付对接（delivery）

验收通过不是结束。设计稿到用户/开发手里能用、不走样，才算交付完成。

## 交付物清单
- **页面/代码**：可运行的最终文件，附调用清单（走了哪几步、用哪条规则）。
- **设计说明**：一句话设计读法（产品/用户/主任务/主操作）+ 关键决策理由（为什么这样排、为什么这个色）。
- **走查点**：列出开发/实施时最容易走样的 3–5 处（如：安全区、空状态、错误态、动效时长）。

## 开发对接（如需）
- 标注：间距/字号/色值/圆角全部来自 `10-tokens.md`，不许口头报数。
- 切图：图标/图片按 1x/2x/3x 出；SVG 优先。
- 状态走查：对照第 7 步的验收项，逐一过 loading / empty / error / 长内容。
- 动效走查：时长/缓动/位移按 `data/motions.csv` 的数值逐项落实，不许"顺滑一点"。

## 上线后
- 记录实际数据表现（如下次迭代的输入）。
- 收集 3 条真实用户反馈，记入下次 00-project 的输入。

## 铁律
- 交付物不含"大概""差不多"——所有数值可查、有源。
- 走查发现的问题回第 7 步修，不许口头约定"以后再改"。
