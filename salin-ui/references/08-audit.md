# 08 · 质量验收（audit）

审查必须基于真实证据（代码静态检查 + 浏览器实际观察互补），不是审美猜测。默认只报告已确认问题，不修改代码。

## 六个维度
任务与流程 / 信息与视觉 / 交互与状态 / 响应式与内容 / 无障碍 / 性能与工程

## WCAG 5 硬门（一票否决，任一不过结论即"不通过"）
1. **对比度**：正文 ≥ 4.5:1，大字（≥18pt / 14pt 粗体）≥ 3:1。占位符/禁用态不豁免。
2. **键盘全流程**：核心流程全程键盘可走完；Tab 顺序符合视觉顺序；焦点始终可见（不许 outline:none 裸奔）。
3. **不只靠颜色传达状态**：错误/成功/警告必须有第二通道（图标/文字/形状）。
4. **触控目标**：移动端 ≥ 44px，桌面端 ≥ 24px；相邻可点击元素间距 ≥ 8px。
5. **减少动态**：prefers-reduced-motion 下非必要动画降级；自动播放必须可暂停。

取证：对比度实算 + 键盘实走 + 系统"减少动态效果"开关复测。

## 关键路径
至少走一条主路径：进入 → 理解状态 → 执行主操作 → 等待 → 成功/失败 → 返回。高风险页加：权限不足、重复提交、断网、空数据、极长内容、移动端、键盘。

## 设计系统漂移分类
- 缺 token：系统没有该语义的值 → 补充或重映射
- 一次性实现：共享组件已存在却被重复实现 → 复用并删除漂移
- 概念不一致：流程/术语/交互形状与相邻功能不同 → 重做体验而非只改 CSS

## 严重度
- P0 阻断：核心任务大范围无法完成，或严重误导难恢复
- P1 严重：主要流程显著受损、关键用户群无法使用
- P2 一般：持续摩擦但可完成（层级/密度/一致性/对比度/响应式）
- P3 轻微：视觉细节、对齐润色

## 报告要求
结论先行 + 高优先级问题（3–5 个最影响任务的）。每项：位置、证据、影响、最小修复建议。只报告可复核的问题；不能证明的标"需浏览器验证"。不为凑数列低价值问题；不把个人审美当规范。

## 完成前检查
- 每个问题有位置/证据/影响/复现或规则依据
- WCAG 5 硬门逐条取证
- 覆盖核心流程、键盘、移动端、完整状态、极端内容
- 删除重复/无关/未经复核的问题
