# 01 · 需求定义（brief）

AI 搭页面翻车，第一因不是审美，是"不知道这页要解决什么"。本步把一句话需求翻译成 `_workbench/spec.md`：每个区块必须对应一个用户问题。spec 是后续所有步骤的唯一需求源。

蒸馏自 @西瓜同学🍉 第18集 /finesse-brief。

## 流程
1. **收需求**：只收一句话——"做什么 + 给谁看"。不写细节、不聊风格。
2. **拆问题**：翻译成用户带着哪几个问题来这个页面（如：参加什么 / 有多难 / 到哪了）。
3. **定区块**：每个问题对应一个区块：区块名 → 用户问题 → 内容要点 → 优先级（P0 必有 / P1 重要 / P2 可砍）。
4. **写 spec**：输出 `_workbench/spec.md`，含"不做清单"（明确写出这次不解决什么）。
5. **过质量门**：说不出解决哪个问题的区块直接删。宁可页面短，不可区块空。
6. **确认**：spec 经用户确认后落盘；需求变更先改 spec 再动手，不许私自加区块。

## spec 必备字段
- 页面一句话目标 / 目标用户
- 区块表（区块 | 用户问题 | 内容要点 | 优先级）
- 不做清单
- 一句话"页面定义摘要"（纯文本，给后续步骤当输入用）

## 铁律
- 区块与用户问题严格 1:1：一个区块回答两个问题就拆；一个问题没人回答就补区块。
- 本步不做视觉判断、不定风格、不写交互细节——越界即错。
