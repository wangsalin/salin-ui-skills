# 六种 Dashboard 侧边栏模式

这些模式抽象自用户提供的侧边栏参考视频。数值是视觉起点；实现时优先映射到项目 token，并根据字体、语言、内容密度和断点验证。

## 快速选型

| 模式 | 最适合 | 不适合 | 核心收益 |
|---|---|---|---|
| 悬浮岛式 Float Panel | 轻量 SaaS、创作工具、柔和画布 | 极高密度后台、边缘空间紧张 | 让导航与页面边缘脱离，画面更轻 |
| 深色重底 Dark Rail | 浅色内容区、运营后台、强品牌锚点 | 已经很暗或低对比的页面 | 用唯一深色面收住整页重量 |
| 磨砂玻璃 Glass Rail | 背后有图片、渐变或动态内容 | 纯色背景、低性能设备 | 建立前后层次和材质感 |
| 双层图标轨 Rail + Panel | 多模块、多工作区、一级与二级导航分离 | 菜单少、层级简单 | 分开“切模块”和“模块内导航” |
| 折叠展开 Hover Expand | 桌面空间紧、图标辨识度高 | 触屏为主、功能陌生 | 兼顾内容空间和完整标签 |
| 分组留白 Grouped Nav | 菜单长、业务组多、账户区要稳定 | 只有 3–5 个入口 | 用分组和滚动职责降低扫描成本 |

## 1. 悬浮岛式（Float Panel）

**视频基线**：侧栏与视口保留约 `16px` 外边距，圆角 `20px`，阴影可从 `0 8px 24px` 起调，页面底色从四周露出。

- 内容区与侧栏共享外层画布间距，避免侧栏悬浮而内容仍贴边。
- 阴影只用于分层，不做厚重黑边。
- 外边距占用真实空间；窄屏减少间距或切换为抽屉。
- 适合约 5–10 个主要入口；长菜单在侧栏内部滚动。

**AI 描述词**：将侧边栏设计为悬浮面板，与视口保留约 16px 外边距、20px 圆角和柔和阴影；页面底色从四周露出。保持内容区与侧栏间距一致，并补齐 active、hover、focus、长菜单滚动和移动端抽屉行为。

## 2. 深色重底（Dark Rail）

**视频基线**：整页唯一大面积深色用于侧栏，示例基色接近 `#171818`；常规标签约 `62%` 亮度/不透明度；当前项用接近 `#FC8805` 的强调色。

- 深色侧栏是视觉锚点；内容区保持更轻，不在各处重复相同深色块。
- 不机械使用 62% 透明度，应在真实背景上验证文字对比。
- 当前项同时改变背景或侧标、文字/图标和语义状态，不只换颜色。
- 品牌色只用于 active、关键状态或极少数操作。

**AI 描述词**：使用深色重底侧边栏作为全页唯一的大面积深色区域；普通导航使用克制浅灰，当前项以品牌强调色、背景/侧标和更高字重共同突出。保持内容区干净，并确保文字对比、focus ring 和暗色主题逻辑完整。

## 3. 磨砂玻璃（Glass Rail）

**视频基线**：约 `12%` 半透明白色面层、`24px` 背景模糊和 `1px` 亮色边缘。

- 只有背后存在可感知的图像、渐变或内容层时，模糊才有意义。
- 使用半透明底色、`backdrop-filter` 和细边框，并准备不支持模糊时的实色回退。
- 在最亮与最暗背景区域验证文字、图标和 active 状态。
- 避免同时叠加强阴影、霓虹描边和多层玻璃卡片。

**AI 描述词**：侧边栏采用克制毛玻璃材质：约 12% 半透明白色面层、24px 背景模糊和 1px 亮色边缘；背后必须有真实背景层。为不支持背景模糊的环境提供实色回退，并验证不同背景下的导航可读性。

## 4. 双层图标轨（Rail + Panel）

**视频基线**：左侧 `72px` 图标轨切换一级模块，右侧约 `240px` 面板显示当前模块的二级菜单。

- 一级轨回答“我在哪个产品/模块”，二级面板回答“当前模块能做什么”。不要把同一层级菜单任意拆成两列。
- 一级图标需要 tooltip、可访问名称和明确选中态。
- 切换一级模块时，明确二级菜单、页面路由和上次位置是否保留。
- 中等宽度可保留图标轨并把面板改为临时抽屉；移动端通常合并为单一抽屉。

**AI 描述词**：采用双层导航，左侧 72px 图标轨切换一级业务模块，右侧约 240px 面板展示当前模块的二级导航。一级切换同步替换面板内容和路由上下文，并定义窄屏时二级面板的抽屉行为。

## 5. 折叠展开（Hover Expand）

**视频基线**：收起 `72px`、展开 `240px`；桌面悬停时以 `ease-out` 展开，标签延后约 `80ms` 淡入。

- 宽度动画不能持续推动主内容。优先覆盖式展开，或仅在固定展开时改变布局。
- hover 只是桌面增强；必须支持点击固定、键盘 `focus-within` 和触屏点击。
- 收起状态保留可辨识图标、`aria-label` 和 tooltip。
- 标签在容器接近展开后淡入并隐藏溢出，避免闪烁。
- 用户偏好可持久化，但不能让桌面偏好破坏移动端。

**AI 描述词**：侧边栏默认 72px，只显示图标；桌面 hover 或键盘 focus-within 时以 ease-out 平滑展开到 240px，标签延后约 80ms 淡入。增加点击固定和触屏替代，并避免动画推动主内容或造成布局抖动。

## 6. 分组留白 + 固定底部收口（Grouped Nav）

**视频基线**：按业务拆为 2–3 组，组间距约 `32px`；组标题约 `11px`、大写、浅灰；底部固定用户区，中间导航独立滚动。

- 分组来自业务心智，不按视觉均匀硬拆。
- 顶部品牌/工作区、中间导航、底部账户/帮助区形成三段布局。
- 中部使用 `min-height: 0` 和独立 `overflow-y: auto`；footer 用 flex 收口，不依赖脆弱绝对定位。
- 11px 大写适合拉丁字母短标签；中文不强制大写，可用约 12px 和适度字距。
- 底部只保留头像、账户切换或一项高频支持入口。

**AI 描述词**：侧边栏按真实业务分成 2–3 组，组间距约 32px；组标题使用 11–12px 弱化标签。整体分为顶部品牌/工作区、中间独立滚动导航、底部固定账户区，确保长菜单不会把用户区挤出视口。

## 组合与边界

- 推荐：`深色重底 + 分组留白`、`双层图标轨 + 分组面板`、`悬浮岛式 + 分组留白`。
- 谨慎：`毛玻璃 + 悬浮岛式`，两者都强调材质，容易过度装饰。
- 避免：`双层图标轨 + hover 整体展开`，层级和宽度同时变化会让位置不可预测。
- 一个方案只保留一个主要视觉记忆点；结构创新与材质创新同时出现时弱化其中一个。

## 侧栏 token

优先复用项目语义 token；确实缺失时再新增：

```text
--sidebar-width-collapsed
--sidebar-width-expanded
--sidebar-gap-page
--sidebar-radius
--sidebar-bg
--sidebar-fg
--sidebar-muted
--sidebar-active
--sidebar-border
--sidebar-shadow
--sidebar-transition-duration
```
