# Dashboard 页面架构

完整 Dashboard 先组织决策路径，再选择组件和视觉风格。侧边栏与图表是系统的一部分，不是页面本身。

## 1. 先写用户问题

把需求改写为最多三个连续问题：

1. **监控**：现在发生了什么，是否偏离目标？
2. **诊断**：变化来自哪里，哪些对象贡献最大？
3. **行动**：用户可以筛选、下钻、处理或导出什么？

无法对应以上任一问题的卡片、图表或装饰应删除或降级。

页面结构任务只解决当前所需层级。不要因为设计 Dashboard 就自动发明接口、异常算法、权限模型或后台任务；实现时确有需要再定义，并将未从项目确认的内容标为建议。

## 2. 三种常见页面

| 页面类型 | 首要目标 | 默认结构 | 常见错误 |
|---|---|---|---|
| 概览 Overview | 快速判断健康度和异常 | 指标摘要 → 主趋势/告警 → 关键分解 → 待办 | 指标太多、每张卡同权重 |
| 分析 Analysis | 解释变化和比较对象 | 筛选/范围 → 主图 → 分解图 → 明细表 | 图表堆叠但没有分析顺序 |
| 运营 Operations | 找到对象并采取行动 | 状态摘要 → 筛选/搜索 → 表格/队列 → 详情/批量操作 | 用大图挤压真正的操作区 |

混合页面要明确主类型；不要让概览、分析和运营三套密度同时抢首屏。

## 3. 页面层级

推荐从上到下组织：

```text
App Shell
├── Navigation / Workspace context
└── Main
    ├── Page context: 标题、范围、更新时间、主操作
    ├── Global controls: 日期、范围、关键筛选、对比口径
    ├── Summary: 2–5 个关键指标或状态
    ├── Primary insight: 回答最重要问题的一张主图或主列表
    ├── Supporting evidence: 分解、构成、异常原因
    └── Action surface: 明细表、待办、详情或导出
```

- 不要求每层都存在；运营页可能直接把表格作为主洞察与行动区。
- 指标摘要只放需要同时比较或监控的关键数；单值没有阈值、变化或上下文时价值有限。
- 主图应获得最清晰的空间和说明，次图不能只是缩小版重复。
- 表格不是“剩余数据容器”，应支持用户从洞察进入具体对象和操作。

## 4. 筛选与状态所有权

先区分范围：

- **全局筛选**：影响整页，应放在稳定位置，并在标题、摘要、图表和表格中一致生效。
- **模块筛选**：只影响单个区块，放在该区块标题附近。
- **视图控制**：改变表现而不改变数据口径，例如图表/表格切换。

定义单一状态来源：URL、页面 store、服务端查询参数或组件局部状态。需要分享、刷新或返回保留的筛选优先进入 URL；纯视觉临时选择可留在组件内。

联动必须说明：

- 全局时间范围变化后哪些请求重新加载。
- 点击图表是否筛选表格、打开详情或只显示 Tooltip。
- 路由返回时是否保留筛选与选中项。
- 数据更新时旧选择是保留、映射还是清除。
- 加载失败时旧数据是否保留，并如何标记陈旧状态。

## 5. 密度与反模板化

- 先用留白、分隔线、对齐和字号建立层级；只有独立交互或表面层级需要卡片。
- 不默认把每个指标放进大圆角卡片，不使用整齐但无业务含义的三列卡片阵列。
- 一个页面只保留一个主要视觉记忆点；强侧栏、强主图、强材质不能同时竞争。
- 工具型后台优先扫描效率和稳定布局，不使用营销页式 hero、装饰光斑或泛泛欢迎文案。
- 颜色承担语义：品牌、状态、告警和数据系列不能混为一套任意彩虹色。

## 6. 响应式重排

移动端按任务重排而不是等比缩小：

1. 侧栏退出文档流，改为抽屉或平台导航。
2. 页面标题保留当前上下文，次级操作进入菜单。
3. 全局筛选显示当前已应用条件，并允许快速清除。
4. 指标摘要横向滚动、两列或纵向排列；不要缩到无法读取。
5. 主洞察优先，次图和明细按任务顺序下移。
6. 图表减少刻度与标签密度，但不隐藏单位、范围和关键值。
7. 表格改为横向滚动、关键列锁定或任务型列表；不要擅自丢列。

## 7. 完整状态

- **Loading**：保持页面骨架稳定；不要让侧栏、筛选和图表分别跳动。
- **Empty**：区分首次无数据、筛选无结果和权限不可见，并给下一步。
- **Error**：说明影响范围和可执行的重试路径；局部失败不必使整页瘫痪。
- **Stale**：保留旧数据时标注更新时间和刷新状态。
- **Permission**：隐藏无权入口，或在业务要求下展示解释性禁用状态；两种策略不要混乱。

## 8. 设计交付检查

完整方案至少能回答：

- 首屏的一个主要判断是什么？
- 哪些筛选影响全页，状态存在哪里？
- 主图和表格如何联动？
- 侧栏在桌面、窄屏和移动端如何变化？
- 零值、缺失、异常、加载、空、错误和无权限如何呈现？
- 用户发现异常后能执行什么动作？
