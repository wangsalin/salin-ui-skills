# Dashboard 项目内实现手册

先理解现有项目，再改页面。不要从孤立 JSX、静态 HTML 或全新组件库开始。

## 1. 实现前检查

确认：

- README、AGENTS/CLAUDE、包管理器、运行命令、当前分支和未提交修改。
- 路由、页面布局、权限/角色过滤和当前页面判定方式。
- 数据获取、缓存、状态管理、错误处理和实时更新方式。
- 已有设计系统、主题 token、断点、图标、国际化与 RTL。
- 已有 sidebar、drawer/sheet、tooltip、scroll-area、collapsible、table 和 chart 封装。
- 已有图表库、motion token、测试栈和浏览器/平台支持范围。

优先复用现有能力；不要为一个 Dashboard 更换框架、升级核心依赖或引入第二套组件库。

## 2. 页面状态边界

状态按职责分层：

- **路由/URL**：需要分享、刷新、返回保留的日期范围、业务范围、筛选和详情 ID。
- **页面查询状态**：请求参数、加载、错误、陈旧数据和刷新。
- **局部交互状态**：当前图表 hover、临时选中、未提交拖动值、侧栏短暂展开。
- **用户偏好**：侧栏固定/收起、密度或主题；确认跨设备和移动端是否适用。

派生值优先计算，不重复存储。避免侧栏、筛选、图表和表格分别维护同一业务条件。

## 3. 侧栏实现

菜单用稳定数据结构驱动，避免在组件中散落权限和 active 判断：

```ts
type NavItem = {
  id: string
  label: string
  href?: string
  icon?: IconType
  children?: NavItem[]
  badge?: string | number
  disabled?: boolean
  external?: boolean
  requiredPermissions?: string[]
}

type NavGroup = {
  id: string
  label?: string
  items: NavItem[]
}
```

- 权限过滤后再渲染，不产生空分组。
- `id` 不使用翻译文本；路由与展示文案解耦。
- active 来自当前路由，不由点击后临时写死。
- 外链、禁用项、子菜单触发器和普通链接使用正确语义。

推荐最小结构：

```text
AppShell
├── Sidebar
│   ├── SidebarHeader
│   ├── SidebarNav
│   └── SidebarFooter
└── MainContent
```

双层导航才增加 `PrimaryRail` 与 `ContextPanel`。侧栏内部使用纵向 flex：header 不滚动，nav 设置 `min-height: 0; overflow-y: auto`，footer 不滚动。主内容只有一个明确滚动所有者。

语义要求：

- 使用 `nav` 与可理解的 `aria-label`。
- 当前链接设置 `aria-current="page"`。
- 折叠按钮使用真实 `button`，设置 `aria-expanded` 和 `aria-controls`。
- 收起标签不重复朗读，链接仍保留可访问名称。
- tooltip 是辅助，不代替标签与可访问名称。

## 4. 图表实现

技术选择顺序：

1. 复用项目已有图表库和封装。
2. 在现有库上增加轻量自定义层或插件。
3. 只有现有库无法满足关键交互时，才评估 SVG、Canvas 或新增依赖。
4. 不为简单图表引入整套大型可视化框架。

常见取舍：

- **SVG**：元素有限、需要 DOM 事件和可访问交互。
- **Canvas**：大量点或高频更新；必须额外设计命中测试和可访问替代。
- **图表库**：复用坐标轴、缩放、Tooltip 和响应式，同时映射到现有主题。

分离但不过度封装以下职责：数据归一化/格式化、几何或配置、交互状态、图例/Tooltip/空错误状态、业务保存请求。

交互要点：

- Pointer Events 同时覆盖鼠标、触控和触控笔；拖动处理指针捕获、边界和取消。
- 移动端命中区以约 `44×44` CSS 像素为起点，可用透明层扩大细线或小柱。
- Tooltip 不遮挡目标且不超出视口；触摸设备能点击关闭或切换目标。
- 键盘焦点可见；方向键、Enter/Space 或输入框能完成关键操作。
- 连续更新时取消或合并旧动画，不排队播放过期状态。
- 容器、字体、侧栏宽度和数据变化后重新测量，避免隐藏容器初始尺寸为 0。

## 5. Dashboard 联动

- 全局筛选只维护一份有效值，并驱动指标、主图、次图和表格使用同一口径。
- 请求可并行时避免瀑布；局部失败只影响相应区块，并说明其余数据是否仍可信。
- 图表选择筛选表格时，提供清晰的已应用条件和清除入口。
- 打开详情后返回，应按产品规则恢复筛选、滚动和选中状态。
- 侧栏宽度或面板开合会影响图表容器时，触发正确 resize；不要仅监听 window。
- URL 状态更新避免每次 hover 写历史记录；只持久化用户确认的筛选或选择。

## 6. 响应式与滚动

| 视口 | 侧栏 | 主内容与图表 |
|---|---|---|
| 宽桌面 | 完整侧栏或固定展开 | 保留完整层级和对比空间 |
| 中等宽度 | 图标轨、覆盖式展开或二级抽屉 | 减少并列列数，主图优先 |
| 移动端 | 退出文档流，使用抽屉/平台导航 | 指标和模块重排，减少标签密度 |

- 移动端抽屉定义滚动锁定、遮罩、Escape、焦点返回和路由切换关闭行为。
- 固定侧栏为主内容提供一次等宽偏移；覆盖式展开不重复偏移。
- 页面避免 body、AppShell、MainContent 多层同时滚动。
- 移动端表格根据任务使用横向滚动、锁定关键列或列表化，但不静默丢数据。
- 处理 `100dvh` 和安全区 `env(safe-area-inset-*)`。

## 7. 动画

- 动画解释展开、数据更新、选择或布局变化，不承担装饰任务。
- 侧栏宽度/位移可从 `160–240ms ease-out` 起调；标签延迟约 `60–100ms`。
- 优先动画 `transform` 和 `opacity`。必须动画宽度时检查主内容和图表抖动。
- 图表首次入场不妨碍读取；实时数据不通过平滑掩盖延迟、缺口或异常。
- `prefers-reduced-motion` 下取消大幅位移、计数和形变，保留即时状态反馈。

## 8. 数据与性能

- 渲染前统一处理时区、排序、缺失值、单位和格式化。
- 大量数据先聚合、采样或虚拟化，不把全部原始点直接绘制到移动端。
- 高频实时数据限制更新频率，避免每个事件完整重绘。
- 稳定复用比例尺、格式化器和配置对象，避免无意义渲染。
- 长菜单、长表格与大量图表同时存在时分别测量滚动和内存，不只看空页面性能。

## 9. 验证顺序

1. 运行项目已有格式化、Lint、类型检查、测试和构建。
2. 在真实路由检查 active、权限过滤、全局筛选和请求参数。
3. 验证普通、零值、负值、缺失、极值、长标签和业务上限数据。
4. 仅用键盘完成侧栏、筛选、图表、表格和详情的关键路径。
5. 用触摸/移动模拟检查抽屉、图表命中区、Tooltip 和滚动。
6. 检查侧栏展开、容器 resize、sticky header、图表和表格是否互相干扰。
7. 验证加载、空、错误、无权限、保存失败、陈旧数据和减少动画。

## 技术栈适配

- React/Next/Vite：复用现有路由 Link、服务端/客户端边界、状态方案和组件库；不要无故把整页改成客户端组件。
- Vue/Nuxt：沿用 router-link、composable/store 与 transition 约定。
- shadcn/ui：优先复用已有 Sidebar、Sheet、Tooltip、Collapsible、ScrollArea、Table 等，只安装真正需要的组件。
- React Native、Flutter、小程序或原生 App：保留数据、交互和验收语义，按平台替换 hover、DOM/ARIA 和浏览器 API。
- 原生 HTML：使用真实链接、按钮、表格和渐进增强，不用 `div` + click 模拟语义。
