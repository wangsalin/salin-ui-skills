# Salin UI Term · 效果术语翻译

## Purpose
"我想要那种……卡片一张张往前翻的感觉"——大白话 AI 听不懂，做出来永远差一口气。本 skill 把效果描述翻译成准确的设计术语（中文名 + English term），术语变成可执行的设计语言，再让 AI"按这 N 条改这一段"。

蒸馏自 @西瓜同学🍉《第18集 | 3个UI设计Skills工作流，让AI做出高级网页》的 /finesse-term：大白话 → Pinned Section / Card Flip / Synced Copy → "按这三条改这一段"，准确实现。

## Workflow
1. **收大白话**：原样记录用户描述。不许用户先想术语——想了也是错的，术语是翻出来的。
2. **拆效果**：一段描述拆成 1–3 条独立效果。多于 3 条说明用户自己没想清楚，打回去让他分开说。
3. **查词典**：`references/term-dictionary.md`，按大白话关键词检索。每条给出：中文术语 + English term + 一句话行为 + 出处标注。
4. **组指令**：输出"按这 N 条改这一段"清单，每条格式：`① 术语（EN）：一句话行为（→ motion 模式编号，如有）`。
5. **交付执行**：把术语清单丢给实现（salin-app-ui / salin-web-ui）或动效（salin-ui-motion）执行，不在本 skill 里写代码。

## Output Contract
- 术语清单（1–3 条）：每条 = 中文术语 + English term + 一句话行为描述 + 出处（视频原话 / 词典 / 推荐译法）
- 可执行指令（一句话）："按这 N 条改这一段：①… ②… ③…"
- 原文大白话存档（一行，备查对账）

## Operating Rules
1. 先拆再翻：多效果混在一起不许直接翻，先拆成独立条再逐条翻。
2. 词典优先：词典有的用词典的；没有的用最接近的术语 + 一句话行为补述，并标注"推荐译法"。
3. 不编造术语：不确定的英文术语，宁可只给中文 + 行为描述，不许生造英文词。
4. 术语是给 AI 执行的，不是给人看的——每条必须能对应到具体实现（motion 模式编号 / CSS 属性 / 组件行为），对应不上的术语等于没翻。
5. 出处诚实：Pinned Section（滚动与固定内容区域）、Card Flip（卡片连续向前翻转）、Synced Copy（左侧文案同步切换）三条标注"视频原话"；其余英文术语一律标注"推荐译法"，不冒充视频原话。
