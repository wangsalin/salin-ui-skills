# Salin App UI

移动端 App / 小程序的界面设计与实现。把界面当成用户完成任务的系统：先理解产品、用户和主操作，再选一个清晰视觉方向并在真实项目中实现。

## 任务路由

| 用户目标 | 必读参考 |
|---|---|
| 从零设计 App 页面 | `references/patterns.md` + `references/design-tokens.md` |
| 改造"不好看、太乱、像模板"的已有页面 | 先列问题清单，再读 `references/patterns.md` |
| 登录、注册、验证码、移动端表单 | patterns.md 表单·向导页 + 输入规范 |
| 在已有代码库中实现 | 先检查项目：README、依赖、路由、组件、tokens、Git 状态 |
| 完成前验收 | 本文件底部「完成前检查」 |

边界按任务目的判断：桌面端网页 → `salin-web-ui`；数据监控、指标诊断、图表联动 → `salin-dashboard-builder`；页面已定、只做 shadcn CLI/组件源码/主题/variants → `salin-shadcn-ui`；功能完成后的只读审查、上线精修 → `salin-ui-quality-audit`。

## 核心流程

1. **确认目标**：页面用户、主任务、主操作、业务约束、可观察的验收标准。非关键缺失可标明假设后继续。
2. **检查现状**：已有项目先读 README、依赖、路由、组件、样式、tokens、环境变量示例和 Git 状态；保留用户未提交修改。
3. **定页面类型**：首页 / 列表页 / 表单·向导页 / 结果·成就页 / 我的·设置页。
4. **取 tokens**：读 `references/design-tokens.md`。默认「暖纸青墨」；深色只给结果/成就页，用暖黑 + 暖金。
5. **选模式**：从 `references/patterns.md` 按页面类型选 1 个主模式 + 最多 2 个辅助模式，一屏一主角。
6. **实现真实界面**：主流程 + loading / empty / error / disabled / 权限 / 长内容 / 弱网状态；不虚构业务不存在的状态。
7. **真实验收**：运行项目已有检查，在真机或模拟器浏览器走关键流程；无法验证的明确说明。

## 设计原则

- 一屏只讲一件事：一个 Hero 或一个主 CTA，不许 N 个平权入口平铺。
- 交互优先级：完成任务 > 理解状态 > 识别层级 > 感受风格。
- 可点击元素最小 44px 高；核心动作放在拇指热区（底部固定按钮或右下 FAB）。
- 空状态不留白：放 3 张建议卡或快捷入口，点一下直接可用。
- 卡片 = 1px 边框 #E5E1D8 + 12~16px 圆角 + 最多 1 层淡阴影。
- 间距只用 8 / 16 / 24 / 32 / 48 五档；列表行高不小于 44px。
- 状态用小胶囊（6px 色点 + 12px 文字），不用大色块；红色只给真实异常。
- 正文灰不浅于 #6B7280；数字、积分、百分比一律 tabular-nums 等宽数字。
- 禁用：大面积渐变背景、玻璃拟态（backdrop-blur）、超过 2 层的阴影、紫蓝色科技风配色、中文 900 字重。
- 组件动效需要时用 `salin-ui-motion`（点按反馈、弹窗过渡、表单校验等 8 种模式）；动效只服务状态变化，不许抢戏。

## 输出契约

复杂任务先给短方案，然后继续执行：

```markdown
## App UI 执行方案
- 设计读法：产品 / 用户 / 主任务 / 主操作
- 页面类型：首页 / 列表页 / 表单·向导页 / 结果·成就页 / 我的·设置页
- 主模式：patterns.md 中的模式名（+ 辅助模式）
- 系统契约：颜色 / 字体 / 间距 / 圆角（tokens 来源）
- 完整状态：加载 / 空 / 错误 / 权限 / 弱网 / 长内容
- 移动端自查：触控尺寸 / 拇指热区 / 安全区 / 刘海屏
- 实现范围：修改内容 / 保持不动 / 验收标准
```

实现任务完成后汇报关键文件、验证结果、未验证内容和残余风险。只做设计建议时，不擅自扩张到数据库、接口或无关页面。

## 完成前检查

- 首屏能否说明当前页面、关键状态和下一步操作。
- 主操作是否在拇指热区；次级操作是否降权；危险操作是否有确认或恢复。
- 所有触控目标 ≥ 44px；安全区、刘海屏、深色模式下无遮挡无闪白。
- 空 / 错 / 加载 / 权限 / 弱网状态是否齐全。
- 是否在真机或模拟器走过关键流程，而不只依赖代码编译通过。
