# Salin UI Layout · 页面/APP 布局

## Purpose
回答"这个页面骨架怎么搭"和"这个页面的布局怎么拆"：24 种常用布局模式的分区、栅格、红线，统一空间系统（`data/spacing.md`），外加一套看图拆布局的九段式分析框架。

## Workflow A — 定骨架（新页面）
1. 先定端（App/Web）与页面类型（首页/列表/详情/表单/营销页/工作台…）。
2. 跑检索：`python scripts/search.py "<页面类型+业务>" --full`，读分区与栅格。
3. 按分区从上到下排布，先定骨架再填组件（组件查 `salin-ui-components`，动效查 `salin-ui-motion`）。
4. 间距/断点/容器一律查 `data/spacing.md`，不许凭感觉定数值。
5. 对照红线自查一遍，命中的当场改。
6. 输出 Layout Spec（见"输出契约"）。

## Workflow B — 拆布局（分析现有页面/App）
输入：截图、链接或文字描述。输出布局拆解报告，固定九段式：
1. **布局模式命名**：命中库中模式则具名（如"信息流+底部Tab"），无命中则用"X+Y 混合"描述，不硬套。
2. **分区拆解**：按视觉顺序列出所有区域（一级分区），注明每个区域的内容与占比。
3. **栅格与间距**：列数/边距/卡片间距/圆角，量不到的写"目测约"，不编精确值。
4. **信息层级**：一级信息（首屏核心）/ 二级（支撑）/ 三级（弱化），指出层级是否清晰。
5. **导航模式**：底部Tab/顶栏/侧边栏/抽屉，评价跳转成本。
6. **评价**：可借鉴点（对照库中模式的优点）+ 问题点（对照红线），每条一句话。
7. **视线动线**：F型（文本阅读）/ Z型（营销页）/ layer-cake（分层蛋糕：标题→视觉→行动），指出首屏视线是否被带偏。
8. **密度分级**：疏（营销/品牌）/ 中（常规）/ 密（工作台/数据），评价密度与场景是否匹配。
9. **触控审计**：App 可点目标 ≥44px、Web ≥32px；列出疑似不达标的区域，截图量不到写"需确认"。

## Query Contract
- 查询词 2–4 个：页面类型 + 业务，如"电商 商品列表""SaaS 工作台""社交 信息流"。
- 分析类任务直接走 Workflow B，不需要先检索。
- 看不清/量不到的不编，标注"需确认"。

## 响应式降级规则
- Web→平板（≤1024）：多列→2列；三栏工作台右栏变抽屉；Bento 大卡片降级为全宽横卡。
- 平板→手机（≤768）：全部单列；侧边栏→底部Tab 或抽屉；分屏页上下堆叠（表单在上）；数据表→卡片列表。
- 触控：App 目标 ≥44px，Web ≥32px；悬停态只做增强，不承载唯一操作。

## 输出契约（Layout Spec）
新页面定骨架必须输出：
- 模式：命中的布局模式（无命中写"X+Y 混合"，不硬套）
- 分区：自上而下/由外而内，带占比或顺序
- 栅格：列数/边距/间距/圆角（数值引用 `data/spacing.md`）
- 断点：768 / 1024 下的降级方式
- 状态：空/加载/错误/超长内容如何处理

## Operating Rules
1. 先骨架后组件：布局阶段不讨论按钮颜色，只讨论分区与层级。
2. 分区必须写占比或顺序，不许"大概分几块"。
3. 每个新页面交付时必须回答：用的哪个布局模式、改了哪里、为什么改。
4. 拆布局报告里"问题点"必须对照库中红线逐条过，不许凭感觉批评。
5. 加新布局 = 在 `data/layouts.csv` 加一行（字段对齐表头），不许改脚本结构。
6. 新页面骨架交付必须带 Layout Spec（模式/分区/栅格/断点/状态），缺一项即不合格。
