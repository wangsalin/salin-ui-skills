# 审查框架

## 六个维度

有充分证据的维度可按 0–4 评分用于内部校准；缺少运行条件、数据或对应范围时标为 `N/A / 未验证`，不要把未验证写成 0，也不要让总分掩盖 P0/P1：

| 维度 | 检查内容 |
|---|---|
| 任务与流程 | 主任务、主操作、反馈、恢复、渐进披露、术语一致 |
| 信息与视觉 | 层级、密度、排版、对齐、颜色语义、设计系统一致性 |
| 交互与状态 | hover/focus/active/disabled/loading/error/success、浮层、表单 |
| 响应式与内容 | 手机/平板/桌面、长文本、空值、大数字、缩放、软键盘 |
| 无障碍 | 语义、键盘、焦点、对比度、名称、动态通知、减少动画 |
| 性能与工程 | 真实瓶颈、布局偏移、资源、长列表、控制台、测试与构建 |

0 = 已确认阻断或完全缺失；1 = 严重不足；2 = 部分可用；3 = 基本扎实；4 = 高质量且经真实验证。只有具备足够代码或运行时证据才评分；总分只作概览，报告仍按严重度排序。

## WCAG 硬门（P0，一票否决项）

以下 5 条任一不满足，审查结论直接判"不通过"，不许用"总体不错"掩盖：

1. **对比度**：正文与背景对比度 ≥ 4.5:1，大字号（≥18pt/14pt 粗体）≥ 3:1。占位符/禁用态文字不豁免——太浅就加深或加图标辅助。
2. **键盘全流程**：核心流程（如下单、支付、提交表单）全程可用键盘走完；Tab 顺序符合视觉顺序；焦点始终可见（不许 `outline: none` 裸奔）。
3. **不只靠颜色传达状态**：错误/成功/警告除颜色外必须有第二通道（图标、文字、形状）。红绿色盲用户能区分吗？不能就改。
4. **触控与点击目标**：移动端 ≥ 44px，桌面端 ≥ 24px（WCAG 2.2 AA）；相邻可点击元素间距 ≥ 8px。
5. **减少动态**：`prefers-reduced-motion` 下所有非必要动画降级为淡入淡出或直接切换；自动播放的轮播/动效必须提供暂停。

取证方式：浏览器 DevTools（Lighthouse Accessibility / 对比度取色）+ 键盘实走 + 系统级"减少动态效果"开关复测。

## 证据来源

### 代码证据

- 精确文件和行号。
- 明确的语义、状态或样式缺失。
- 可追踪的数据、权限和路由行为。
- 测试、lint、类型和构建的真实输出。

### 运行时证据

- 页面/路由、视口、主题和账号角色。
- 可复现步骤、预期与实际结果。
- 屏幕截图、录屏、控制台、网络和性能数据。
- 键盘、触摸、缩放、慢网和极端数据行为。

静态代码通常不能独立证明视觉层级不好；单张截图也不能证明焦点、错误恢复或响应式完整。

## 关键路径采样

至少选择一条主路径：进入 → 理解状态 → 执行主操作 → 等待 → 成功/失败 → 返回或继续。高风险页面增加：权限不足、重复提交、断网、空数据、极长内容、移动端、键盘。

## 设计系统漂移

将偏差归类为：

- **缺 token**：系统没有表达该语义的值；应补充或重新映射 token。
- **一次性实现**：共享组件已存在却被重复实现；应复用并删除漂移。
- **概念不一致**：流程、信息架构、术语或交互形状与相邻功能不同；应重做体验而非只改 CSS。

## 性能审查

没有测量就不下“性能很差”的结论。可先报告明显风险，例如未分页的一万行列表、未设置尺寸的大图、阻塞主线程的同步计算；若要判断影响，采集 LCP、INP、CLS、请求、bundle 或 profiler 数据，并对比修改前后。

## 当前规范取证

用户要求按“最新、当前、合规”审查时必须联网，并优先使用标准组织或产品官方一手来源。先确认适用范围：通用 Web 无障碍、平台 HIG、组件库规范或地区法规不是同一标准。每项引用记录：规范名称、版本、正式标准/草案/解释材料、发布日期或最后更新日期、具体条款 ID、页面 URL 和访问日期。正式标准优先于草案，条款优先于二手文章；解释材料只能帮助理解，不能替代规范条款。无法联网或无法确认适用版本时，标记“最新性/合规性未验证”，不得给出合规结论。

## 复核门槛

写入报告前回答：

1. 这是缺陷还是个人偏好？
2. 能指出具体位置吗？
3. 能复现或由明确规则证明吗？
4. 对用户或业务有什么可描述的影响？
5. 最小、可执行且不扩大范围的修复是什么？

任一关键问题答不上来时，改写为“待验证”或删除。
