# 常见反模式

这些是高价值审查线索，不是看到一次就自动判错。结合产品语义、设计系统和真实影响复核。

## 模板化视觉

- 与品牌无关的紫蓝渐变、发光球、背景网格和装饰噪点。
- 每个内容块都是相同大圆角卡片，卡片内继续嵌套卡片。
- 默认玻璃拟态、渐变文字、宽阴影 + 重边框同时使用。
- Hero + 三张指标卡 + 一组同构卡片被套到任何产品。
- 到处使用 tiny uppercase eyebrow、胶囊标签和编号章节。
- 米白 + 衬线标题 + 砖红强调成为无语义的“高级”默认值。
- 暗色页面自动变霓虹、酸性绿、伪终端或赛博风。

## 层级与排版

- 主标题超大却没有传达更多信息；常规产品 Hero 一般不应无限放大，约 6rem 以上需强理由。
- 标题字距过度收紧；正文行长长期超过约 65–75ch。
- 标题、正文和辅助文字几乎同级，或只靠灰度表达层级。
- 超过三种字体家族、过多字号/字重或随机 13px 间距。
- 卡片圆角普遍超过 32px，控件被迫胶囊化，密度与任务不匹配。

## 交互与状态

- 只设计 hover，没有 focus 或触摸替代。
- placeholder 代替 label，错误只用红色边框，焦点 outline 被移除。
- 通用“发生错误”没有原因、影响、重试或恢复。
- Dropdown 被祖先 overflow 裁切，Dialog 没有焦点管理，Toast 替代字段错误。
- Loading 让整个界面不可用，或异步按钮可重复提交。
- 手势是唯一入口，危险操作每次确认但没有撤销。

## 产品与文案

- 按数据库字段或组织架构组织页面，而不是用户任务。
- 四十个设置字段一次暴露，或营销语言出现在运营工具的高频流程。
- “赋能、革新、无限可能、开启旅程”等文案换成任何产品仍成立。
- 按钮写“确定、继续、提交”却不说明动作对象和后果。
- 同一对象在不同页面被称为 Workspace、Project、空间或项目。

## 工程与性能

- 硬编码颜色/间距绕过 tokens，已有共享组件却重复实现。
- 动画 width/height/top/left 导致布局抖动，忽略 reduced motion。
- 图片未设置尺寸导致 CLS，长列表一次渲染全部数据。
- 不测量就声称性能已优化，或只用桌面高速网络测试。
