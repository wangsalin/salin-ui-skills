# 视觉方向

先从产品语义选择一个主方向。新设计或用户允许重塑视觉时，再加一个与业务内容有关的记忆点；成熟设计系统中的局部实现不强行新增风格。不要把多个方向平均混合，也不要用“高级感”代替具体判断。

## 方向库

| 方向 | 适用 | 关键特征 | 避免 |
|---|---|---|---|
| Calm Product Minimal | AI 工具、效率产品、设置页 | 大留白、克制边界、清晰排版、少量强调色 | 空白过多导致信息松散 |
| Dense Operator Console | CRM、客服、运营、内部工具 | 紧凑行高、固定操作区、强筛选、扫描优先 | 用大卡片和大标题浪费空间 |
| Consumer App Clean | 消费 App、会员、预约 | 友好比例、短路径、明显主操作、触控优先 | 可爱元素破坏任务效率 |
| Local Merchant Warmth | 餐饮、门店、本地服务 | 暖中性色、真实图片、朴实可信文案 | 奶油色模板和过度手写感 |
| Swiss Utility | 工具、文档、专业服务 | 网格、强对齐、黑白灰、少量信号色 | 形式主义排版影响阅读 |
| Editorial Premium | 品牌、内容、作品集 | 杂志式层级、图文节奏、精确留白 | 默认衬线 + 米白 + 砖红的 AI 套路 |
| Technical Industrial | 工业、开发者、设备 | 技术排版、状态色、参数清晰、稳定结构 | 伪终端、霓虹和无意义扫描线 |
| System Native | Apple-like、桌面工具、设置 | 内容优先、细腻分隔、轻材料感、克制动效 | 只堆磨砂、透明和大圆角 |
| Visual Landing | 官网、发布页、活动页 | 首屏命题明确、强主视觉、章节节奏 | 产品后台式卡片拼盘 |

## 设计系统契约

在实现前明确：

- 颜色：1 套中性色、1 个主强调色、语义状态色；新项目可优先 OKLCH，现有项目保持原色彩模型。
- 字体：正文、标题、数字/代码等角色；正文行长通常控制在 45–75 字符。
- 层级：字号、字重、留白和位置共同表达，不能只靠颜色。
- 间距：使用 4 或 8 的基础尺度，少量光学校正要有理由。
- 圆角：按控件、容器、浮层分级；普通卡片不要普遍超过 24–32px。
- 阴影：只表达浮层和层级，不与重边框叠加制造“贴纸感”。
- 图标：同一图标族、统一描边与尺寸；不把 emoji 当产品图标。
- 动效：150–300ms 为常见反馈区间，说明进入、退出和减少动画行为。

## 一个记忆点

记忆点应来自主题，例如餐饮产品的真实出品节奏、写作工具的编辑轨迹、制造系统的工艺状态，而不是通用光斑。一次只选择一个：独特排版、信息可视化、材质处理、内容运动或品牌化控件。

## 反模板检查

- 是否出现与品牌无关的紫蓝渐变和发光球。
- 是否每块信息都被装进相同圆角卡片。
- 是否用三张指标卡 + 大 Hero 冒充产品结构。
- 是否大量使用玻璃、渐变字、胶囊标签和 tiny uppercase eyebrow。
- 是否文案空泛，换成任何产品也成立。
- 是否为了视觉效果牺牲密度、对比度、响应式或真实状态。
