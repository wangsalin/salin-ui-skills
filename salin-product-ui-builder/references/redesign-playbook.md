# 已有页面改造

先诊断再修改。目标是找出结构性问题，不是把所有颜色、圆角和阴影换一遍。

## 诊断顺序

1. 用户在这里完成什么，主路径是否连贯。
2. 主操作、次级操作、危险操作是否有明确优先级。
3. 信息是否按用户心智组织，还是按字段和组件堆叠。
4. 页面密度是否适合任务：运营工具看扫描效率，营销页看叙事节奏。
5. 表单、列表、导航和反馈是否符合相邻页面的既有惯例。
6. loading、empty、error、权限、长文本和移动端是否缺失。
7. 视觉问题属于缺 token、没有复用组件，还是概念/流程不一致。

## 优先级

- P0：无法完成任务、数据或权限误导、关键无障碍阻断。
- P1：主路径混乱、主操作不清、移动端不可用、状态缺失。
- P2：层级、密度、排版、颜色语义和组件一致性问题。
- P3：微小对齐、阴影、动效、文案和视觉润色。

先处理 P0/P1，再建立 tokens 和结构，最后做视觉润色。不要在错误流程上做像素级精修。

## 改造策略

- 保持业务能力、路由、权限和数据口径，除非用户明确要求改变。
- 先复用项目组件；重复出现的修复才抽成共享模式。
- 每轮改变一个层次：结构 → 组件 → 视觉 → 动效，便于比较和回滚。
- 用真实数据和极端数据检查，避免只用理想占位内容。
- 对“高级感”给出可验证定义，例如更清晰层级、更稳定密度、更少视觉噪音，而不是纯审美形容词。
