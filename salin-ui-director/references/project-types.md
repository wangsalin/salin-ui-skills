# 项目类型判断

UI 方案先判断页面属于哪类产品表面。不同类型的“好看”标准不同。

## 类型表

| 类型 | 目标 | UI 优先级 | 避免 |
|---|---|---|---|
| SaaS 后台 | 高效完成任务 | 导航、表格、筛选、状态、密度 | 营销式 hero、过度装饰 |
| CRM/运营工具 | 重复录入和跟进 | 表单、列表、批量操作、清晰反馈 | 大卡片堆叠、弱输入边界 |
| AI 工具 | 输入、生成、迭代 | 输入区、结果区、历史、成本/状态 | 只做聊天框，没有工作流 |
| 数据看板 | 快速判断趋势 | 指标层级、图表解释、筛选 | 只堆数字，无业务含义 |
| 移动端表单 | 快速提交 | 主按钮、输入、键盘、错误状态 | 过小控件、文案太长 |
| 登录/认证 | 建立账号身份 | 主登录方式、验证码、协议、错误 | 第三方登录抢主线 |
| 官网/品牌页 | 建立信任和转化 | 首屏主体、证据、行动 | 空泛价值主张、假图 |
| 电商/商品页 | 促成购买/询盘 | 商品信息、价格、保障、CTA | 花哨布局盖过购买路径 |
| 本地生活页 | 到店/预约/团购 | 门店位置、价格、理由、转化 | 泛流量风格、不显示地点 |
| 工厂 B2B 页 | 询盘和信任 | 产品、工艺、质检、案例、需求表 | 只喊源头厂家和低价 |

## 判断问题

动手前先回答：

1. 用户来这个页面要完成什么动作？
2. 页面第一屏必须让用户知道什么？
3. 主要信息是输入、浏览、比较、购买、询盘还是管理？
4. 用户会高频使用，还是一次性转化？
5. 移动端和桌面端谁优先？

## 决策规则

- 高频工具：密度、稳定、清晰大于惊艳。
- 转化页面：主体、证据、信任、CTA 大于装饰。
- AI 产品：工作流、结果可控、失败可恢复大于“科技感”。
- B2B：证据和风险控制大于情绪化文案。
