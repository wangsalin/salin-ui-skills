# 苹果风格落地规范

当用户要求“苹果风格、Apple-like、iOS、macOS、Human Interface、高级系统感”时，把它理解为系统级产品气质，不是视觉特效模板。

## 判断是否适合

适合：

- AI 工具、创作工具、个人效率工具、移动端 App、轻量 SaaS。
- 硬件/软件官网、品牌化产品页、需要精致可信的消费级产品。
- 需要长期使用、低噪、清晰、安静的产品界面。

谨慎使用：

- 重运营 CRM、超高密度表格后台、强促销电商、低价转化页。
- 这些场景可以借鉴苹果式层级、控件和动效，但不能牺牲效率、密度和业务转化。

## 核心原则

- **内容优先**：首屏先给任务、状态和主操作，不用装饰性大标题占满空间。
- **系统秩序**：稳定字号层级、明确控件分组、可预测导航，不混用多个视觉语言。
- **真实留白**：留白服务分组和呼吸感，不把表格、表单和工具页撑成展示页。
- **轻材料感**：半透明、背景模糊、细边框和柔和阴影只用于导航、浮层、工具栏、侧栏等材料层。
- **克制动效**：动效表达状态变化，短时长、自然缓动，支持 reduced motion。
- **可长期使用**：低噪色彩、足够对比度、清晰 focus、稳定布局。

## Web / Tailwind / shadcn 落地

- 使用系统字体栈或项目已有 sans-serif；不要为“苹果感”随意引入装饰字体。
- 使用语义 token：`background`、`foreground`、`card`、`muted`、`border`、`ring`、`accent`。
- 优先改 `globals.css`、Tailwind token 和 `components/ui/*`，不要在业务页面散落大量苹果风格 class。
- 主容器圆角通常 12-20px；按钮、输入和小控件遵循现有组件系统。
- 阴影要轻：优先边框和层级，少用大范围模糊投影。
- `backdrop-blur` 必须有可读性兜底：边框、实色背景、对比度和移动端性能考虑。
- 复杂工具页采用“侧栏/顶部栏 + 主工作区 + 检查器/结果区”，不要做成官网 hero。

## iOS / 移动端重点

- 触控目标至少 44px。
- 使用 `100dvh` 或 `100svh` 处理移动浏览器工具栏，不依赖 `100vh`。
- 底部主操作、抽屉、验证码按钮、协议区不能被键盘或浏览器工具栏遮挡。
- 表单和验证码输入要有清晰 label、错误、倒计时和禁用状态。
- 390px 和 430px 必查；320px 作为极限兜底。

## macOS / 桌面应用感

- 适合用侧栏、顶部工具栏、分栏、列表详情、检查器面板。
- 导航、筛选、对象列表和详情操作应稳定在固定区域。
- 支持键盘焦点、hover、选中态、空态和权限态。
- 不要为了 macOS 感把 Web 页面做得像假系统窗口，除非产品明确是桌面应用。

## 官网 / 品牌页重点

- 首屏要清楚显示产品主体，真实产品截图、界面或设备画面优先。
- 大标题可以更有呼吸感，但必须留下下一段内容线索。
- 一个记忆点足够：产品截图构图、材料层、交互动效、品牌色或排版节奏。
- 不要照搬 Apple 官网的超长滚动叙事，除非内容和素材足够支撑。

## 禁区

- 不把苹果风格等同于毛玻璃、巨大圆角、银灰背景和浅色卡片。
- 不复制 Apple 官网布局到后台、表格、CRM 和表单流。
- 不使用满屏模糊渐变、光斑、漂浮设备壳、假 3D 截图来掩盖信息结构。
- 不为了“高级”降低按钮可发现性、输入边界、错误提示和移动端触控效率。
- 不把所有东西都做成透明卡片；材料层必须表达真实层级。

## 验收

- 三秒内能看懂页面任务和主操作。
- 字号、留白、圆角、阴影、边框来自统一规则。
- 材料层不会降低可读性或性能。
- 移动端没有键盘遮挡、按钮溢出、抽屉越界。
- 动效关闭后页面仍完整可用。
