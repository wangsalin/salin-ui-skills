# 重设计诊断

改已有界面前先诊断，不要直接换色、加阴影或重写布局。目标是找出影响任务完成的真实问题。

## 诊断问题

1. 用户来到这个页面最想完成什么动作？
2. 当前最强的视觉元素是不是这个动作？
3. 页面看起来是产品界面、运营后台、表单流程，还是被误做成了营销页？
4. 主操作、次操作、危险操作是否有清晰权重？
5. 输入、筛选、表格、弹窗是否有可见边界和反馈？
6. 是否缺少 loading、empty、error、disabled、success、permission 状态？
7. 320px、390px、430px、768px、1440px 下是否有溢出、遮挡、错位？
8. 文案是在帮助用户操作，还是在解释功能和喊口号？
9. 颜色、圆角、阴影、图标、字号是否有统一规则？
10. 是否存在 AI 模板痕迹：紫蓝渐变、光斑、毛玻璃、巨大圆角、等宽卡片网格、泛泛文案？

## 修改优先级

1. 重排信息和操作顺序，让主路径自然。
2. 调整视觉权重，让主操作最明显。
3. 修复输入、筛选、表格和弹窗的可用性。
4. 补齐缺失状态和错误恢复。
5. 精简文案，改成用户能执行的动作语言。
6. 统一 token：颜色、字体、圆角、边框、阴影、间距。
7. 最后再加动效、材质、品牌记忆点。

## 常见问题和处理

| 问题 | 影响 | 优先改法 |
|---|---|---|
| 顶部装饰区太大 | 主任务被压到首屏下方 | 收缩为页面标题和操作区 |
| 所有按钮一样重 | 用户不知道下一步 | 明确 primary/secondary/tertiary |
| 输入框像文字区域 | 表单可发现性差 | 增加 label、边界、focus、错误 |
| 表格外层套多层卡片 | 信息密度低、扫描慢 | 用分区、边框、工具条替代 |
| 空状态只有插画 | 用户不知道怎么恢复 | 加原因和下一步动作 |
| 错误文案是后端信息 | 用户无法理解 | 改为本地化、可恢复文案 |
| 大量 hex 散落 | 后续难维护 | 收敛到语义 token |
| 毛玻璃/光斑很多 | 模板感强、可读性差 | 只保留有层级意义的材质 |

## 最终读法

改完后三秒内应能说清：

`这是 <产品/页面>，我可以 <主操作>，遇到问题时可以 <恢复动作>。`
