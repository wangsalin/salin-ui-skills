# GSAP 动效策略

GSAP 用于增强关键状态变化，不用于替代 UI 设计。

## 先确认两件事

1. 项目是否已经安装 `gsap` npm 包。
2. 是否真的需要复杂动效；简单 hover/transition 用 CSS 即可。

如果项目没装 GSAP，需要在具体项目里安装运行库，例如 `npm install gsap`、`pnpm add gsap`。`GSAP skill` 只是写法参考，不等于项目已有依赖。

## 适合使用 GSAP

- 首屏内容有组织地进入。
- 列表、卡片、表格行 stagger 出现。
- 数字变化、进度变化、生成状态。
- 页面切换或面板展开需要时间线控制。
- 鼠标跟随、拖拽、复杂 SVG/Canvas 动效。

## 不适合使用 GSAP

- 普通按钮 hover。
- 只需要 opacity/transform 的简单 CSS transition。
- 表单、后台、CRM 里的高频基础操作。
- 移动端性能敏感页面的大面积动画。
- 用户开启 `prefers-reduced-motion: reduce` 时。

## 动效原则

- 动效必须解释状态变化：进入、切换、生成、完成、失败。
- 优先动画 `transform` 和 `opacity`。
- 避免动画 `width`、`height`、`top`、`left` 等布局属性。
- 使用 timeline 管理复杂顺序，不用一堆 delay 硬排。
- 组件卸载或页面切换时清理动画。

## 典型模式

| 场景 | 建议 |
|---|---|
| 页面进入 | 标题、主操作、内容块按层级进入，200-600ms |
| 卡片列表 | `stagger` 轻微上移 + fade，不要弹跳过度 |
| AI 生成中 | 进度、光标、结果块逐步出现 |
| 数据切换 | 数字和图表用短过渡，保持可读 |
| 移动端 | 动效更短、更少，避免滚动卡顿 |

## 验收

- 降低动效模式下可用。
- 页面首屏不因动画延迟主操作。
- 动效不造成布局跳动。
- 控制台无动画相关报错。
